# 신규 동호회 온보딩 체크리스트

온볼(OnBall)에 새 동호회를 붙일 때 쓰는 실무 문서.
**질문 → 설정값 → 실행** 순서로 되어 있다. 동호회 담당자와 통화하면서 위에서부터 채우면 된다.

---

## 0. 먼저 알아둘 것

- 온볼은 **플랫폼**이고 동호회가 고객이다. 각 동호회 회원은 **자기 동호회만** 본다.
- 통계·어워즈·배지·화면은 **전 동호회 공통**이다. 한 곳을 고치면 모두에게 반영된다.
- 동호회마다 다른 건 **운영 룰(`rules`)** 과 **데이터**뿐이다.
- 계층: `조직(orgs) → 팀(teams) → 시즌(leagues) → 세그먼트(league_quarters)`
  - 조직 = 로고·회원계정·관리자를 공유하는 단위 (예: 파란날개)
  - 팀 = 명단·기록이 격리되는 단위 (예: 청년부 / 장년부). 하나뿐이면 `main`
  - 시즌 = **1년**. 2026 시즌, 2025 시즌.

---

## 1. 동호회에 물어볼 것

### 1.1 기본 정보

| 항목 | 질문 | 들어갈 곳 |
|---|---|---|
| 동호회 이름 | 정식 명칭이 어떻게 되나요? | `org.name` |
| 영문 약칭 | URL에 쓸 짧은 영문 이름이 필요합니다 (예: `miracle`) | `org.slug` |
| 팀 구분 | 청년부/장년부처럼 명단이 나뉘나요? | `team.slug` (없으면 `main`) |
| 편집 PIN | 기록 담당자가 쓸 4자리 숫자를 정해주세요 | `team.edit_pin` |
| 운영 형태 | 내부에서 팀 나눠 리그를 하나요, 외부 대회에 나가나요? | `season.mode` |
| 시즌 시작일 | 올해 첫 경기가 언제인가요? | `season.start_date` |

> **`org.slug` 는 나중에 바꾸기 어렵다.** URL(`/league/<slug>/2026`)에 들어가고 회원들이 북마크한다. 짧고 안 헷갈리는 걸로 확정한 뒤 넘어갈 것.

### 1.2 운영 룰 — 여기가 핵심

기본값은 **국내 동호회 자체전 관행**에 맞춰져 있다. 아래를 물어서 다른 것만 예외로 준다.

| 질문 | 기본값 | 다르면 설정할 곳 |
|---|---|---|
| **2점슛 파울 때 자유투 몇 개, 몇 점인가요?** | 1구 2점 (`ft_2pt: 2`) | `rules.event_points.ft_2pt` |
| **3점슛 파울 때는요?** | 2점 + 1점 (`ft_3pt_1: 2`, `ft_3pt_2: 1`) | 같은 블록 |
| **일반 자유투(테크니컬 등)는 1점 맞나요?** | 1점 (`free_throw: 1`) | 같은 블록 |
| **나이 등으로 점수를 더 주는 규정이 있나요?** | 없음 (`plus_one_bonus.amount: 0`) | `rules.plus_one_bonus.amount` |
| **하루에 여러 경기를 하나요?** | 경기 단위 (`round_unit: "game"`) | 하루 통합이면 `"day"` |
| **한 쿼터 몇 분, 몇 쿼터인가요?** | 10분 4쿼터 | `rules.period` |
| **파울과 출전시간을 기록하시나요?** | 둘 다 기록 | `rules.tracking` |

**플러스원 예시 (미라클모닝):** 만 50세 이상 선수는 야투 성공 시 +1점. 2점슛 → 3점, 3점슛 → 4점.
자유투와 앤드원에는 붙지 않는다. 이런 규정이 있으면 `amount: 1` 로 준다.

> 자유투 배점은 **동호회마다 가장 자주 갈리는 항목**이다. 반드시 확인할 것.
> 여기가 틀리면 득점·어워즈·더블더블이 전부 어긋난다.

### 1.3 명단·일정

| 항목 | 질문 |
|---|---|
| 선수 명단 | 이름 · 등번호 · 포지션. 엑셀이나 카톡 명단으로 받으면 된다 |
| 내부 팀 | (리그형만) 시즌에 몇 팀으로 나누나요? 팀 이름은? |
| 시즌 구분 | 분기로 나누나요? (미라클은 26.1Q~26.4Q. **기본은 구분 없음**) |
| 유튜브 채널 | 하이라이트를 올리는 채널이 있나요? |

## 2. 설정 파일 만들기

`scripts/onboard-samples/example-club.json` 를 복사해서 값을 채운다.

```jsonc
{
  "org":  { "slug": "hoopers", "name": "후퍼스 농구회" },
  "team": { "slug": "main", "name": "후퍼스", "edit_pin": "1234" },
  "season": {
    "slug": "2026", "name": "후퍼스 2026", "year": 2026,
    "mode": "league", "start_date": "2026-09-01"
    // 룰이 기본값과 같으면 rules 를 아예 안 쓴다
  },
  "matchTeams": ["레드", "블루"],
  "players": [{ "name": "홍길동", "number": 7, "position": "PG" }]
}
```

룰이 다른 경우에만 `season.rules` 를 추가한다 — **다른 항목만** 쓰면 나머지는 기본값이 유지된다:

```jsonc
"rules": {
  "plus_one_bonus": { "amount": 1 },      // 나이 가산 규정이 있는 경우
  "round_unit": "day",                    // 하루에 여러 경기를 하는 경우
  "event_points": { "ft_2pt": 1 }         // 자유투가 일반 룰(1점)인 경우
}
```

## 3. 실행

```bash
# 1) 검증만 — DB 를 건드리지 않는다
node scripts/onboard-club.mjs <설정파일.json>

# 2) 문제 없으면 실제 생성
node scripts/onboard-club.mjs <설정파일.json> --commit
```

출력에 접속 주소(`/league/<org>/<season>`)와 편집 PIN 이 나온다.

## 4. 생성 후 확인

- [ ] `/league/<org>/<season>` 접속되고 팀·선수가 보이는가
- [ ] `node scripts/verify-schema.mjs` 통과 (기존 동호회에 영향 없음 확인)
- [ ] 설정 화면에서 편집 PIN 으로 진입되는가
- [ ] 룰이 맞게 들어갔는가 —
      `node scripts/db-migrate.mjs sql "select org_slug, rules from leagues where org_slug='<slug>'"`
- [ ] 테스트 경기 하나를 기록해 **득점이 그 동호회 룰대로 계산되는지** 확인
      (특히 자유투 · 플러스원이 있으면 반드시)

## 5. 아직 안 되는 것 (온보딩 전 알려줄 것)

| 항목 | 상태 |
|---|---|
| 어드민 화면의 "조직 만들기" / "리그 만들기" 버튼 | **동작 안 함** — 이 스크립트로 대신한다 (단계 7에서 재설계) |
| 동호회별 로고·브랜드 컬러 | 미구현. 화면은 온볼 톤(옐로/블랙) 고정 |
| PWA 앱 이름 | 미라클 고정 — 설치형 앱은 아직 동호회별로 안 갈린다 |
| 드래프트 기능 | 미라클 전용. 다른 동호회는 못 씀 |
| 상대팀 선수 기록 (대회형) | 개발 예정 |

---

## 6. 회원 가입 안내 (동호회에 전달할 내용)

1. `/league/<org>/<season>` 접속 → 우측 상단 **로그인**
2. 이름 선택(명단에서 자동완성) + 생년월일 입력 → 가입 요청
3. **운영자 승인** 후 이용 가능 (설정 화면에서 승인)
4. 초기 비밀번호 = **생년월일 6자리(YYMMDD)** → 로그인 후 변경 안내

공개 범위: 박스스코어·일정·명단·순위표는 누구나, **시즌 스탯·어워즈·하이라이트는 승인 회원만**.
