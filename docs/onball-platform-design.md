# 온볼 플랫폼화 설계 — 여러 동호회를 담는 그릇으로 (2026-11-10)

> 목표: 미라클에서 시작해 미라클에만 맞춰진 부분을 걷어내고, **새 동호회를 CEO 콘솔(/admin)에서 몇 단계로 온보딩**할 수 있게 한다.
> 원칙: **기능은 하나, 동호회마다 다른 점은 「설정」으로.** 미라클 화면·숫자는 단계마다 그대로여야 한다.

## 진행 상황 (2026-11-10)
- 1단계 완료 · 2단계 완료(마이그레이션 135 적용) · 3단계 완료(기능 스위치를 서버 입구·메뉴·가이드에 적용) · 4단계 완료(`/admin/clubs/new` 마법사 — 이름·주소 → 견본(전부 쓰기/기록만) → 경기 팀·명단 붙여 넣기 → 어드민 → 가입 링크·단톡방 안내 복사). 남은 것: 5단계 · 6단계.
- 아직 설정만 저장되고 화면에 안 쓰이는 값: `team_count`(팀 수) · `record_fouls`(파울 기록 — 리그 화면은 파울을 안 그린다) · `roster_mode`. 4·5단계에서 쓴다.

## 1. 지금 구조 (2026-11-10 실측)

### 1-1. 시스템이 두 벌이다

| | **팀 시스템 (옛것)** | **리그 시스템 (새것)** |
|---|---|---|
| 동호회 | 파란날개 청년부·장년부 | 미라클모닝농구단 |
| 주소 | `/paranalgae/youth` | `/league/miracle/<리그 id>` |
| 명단 표 | `players` (청년부 38 · 장년부 32) | `league_players` (51) |
| 경기 | `tournaments`·`games` (대회 17개) | `leagues`(리그 1 · 대회 1) · `league_games` |
| 로그인 | 없음 — 편집 PIN 하나 | 회원 계정 · 어드민 역할 · CEO |
| 월렛·참가신청·드래프트·하이라이트 | 없음 | 있음 |
| 코드에서 옛 표를 직접 읽는 파일 | 22개 | — |

공통 그릇은 `teams` 표 하나다(동호회 = `teams` 한 줄). 그 아래가 시스템마다 다르다.
- 미라클: `teams` → `leagues`(리그·대회 묶음) → `league_teams`(락다운 등) · `league_players`
- 파란날개: `teams` → `tournaments` · `players`

### 1-2. 용어가 겹친다 (⚠ 플랫폼화의 가장 큰 걸림돌)

| 실제 뜻 | 코드·DB 이름 | 문제 |
|---|---|---|
| 동호회 (미라클) | `teams` | 「팀」인데 동호회를 뜻한다 |
| 동호회 안의 팀 (락다운) | `league_teams` | 진짜 팀 |
| 시즌 묶음 (2026 리그) | `leagues` | 「리그」인데 한 시즌을 뜻한다 |
| 조직 | `orgs`, `teams.org_slug` | 거의 안 쓰는 옛 칸 |

→ **화면·문서에서는 「동호회 · 시즌 · 팀」으로 부르고, DB 이름은 당장 바꾸지 않는다.** 이름 변경은 위험만 크고 얻는 게 적다. 대신 코드에 별칭 타입(`Club = teams 행`)을 두어 새 코드가 헷갈리지 않게 한다.

### 1-3. 지금 /admin 화면

| 주소 | 하는 일 | 문제 |
|---|---|---|
| `/admin` (대시보드) | 「토너먼트」 칸(옛 팀 목록 + 새 팀 추가) · 「리그」 칸(최근 리그 + 새 리그) · 이벤트 내려받기(「미라클 리그」·「파란날개」 카드 고정) | 동호회가 시스템별로 갈라져 보인다. 문구에 미라클·파란날개가 박혀 있다 |
| `/admin/teams/new` | 옛 팀 시스템 팀 만들기(이름·주소·색·**PIN**) | 새 동호회도 PIN 시스템으로 만들어진다 |
| `/admin/teams/[id]` | 팀 이름·PIN·대회 목록 | 운영 설정·기능·어드민이 없다 |
| `/admin/leagues` · `/new` · `/[id]` | 시즌 만들기 · 어드민 지정 · 드래프트 | 동호회가 아니라 시즌 단위라, 동호회 하나를 보려면 여러 화면을 돈다 |
| `/admin/admins` | 공동 관리자 | 그대로 둬도 됨 |
| `scripts/onboard-club.mjs` | 명령줄 온보딩 | 화면이 없어 CEO 가 직접 못 한다 |

### 1-4. 코드에 박힌 미라클 값

| 종류 | 예 | 대략 |
|---|---|---|
| 요일 | 「토요일」 문구·판정 | 23개 파일 |
| 입금 방식 | 「모임통장」, 카카오뱅크 알림 파싱 | 10개 파일 |
| 동호회 이름 | 「미라클」 (상당수는 설명 메모) | 61개 파일 |
| 고유 번호 | 로고 매핑 `leagueLogo.ts` 의 미라클 리그 id | 1곳 |
| 운영 가정 | 3팀 로테이션 · 하루 9~10경기 · 분기 드래프트 · 달별 정규 · 파울 미기록 · +1 보너스 | 기능 곳곳 |
| 가격 | 정규권 28,000P · 비정규 12,000P (가이드 문구) | 가이드 2개 |

이미 설정으로 빠진 것: `leagues.games_per_round`(경기 수) · `leagues.rules`(득점 규칙·+1) · `leagues.rsvp_rules`(신청 요일·정원) · `teams.wallet_name/bank/rules`(월렛) · `teams.is_public`.

## 2. 목표 그림

```
온볼
 └─ 동호회 (teams 한 줄)            ← 운영 설정 · 기능 스위치 · 로고 · 공개 여부 · 어드민
     ├─ 시즌 (leagues: 리그 / 대회)  ← 시즌 기간 · 경기 방식(동호회 기본값을 이어받음)
     │   ├─ 팀 (league_teams)
     │   └─ 경기 · 기록
     ├─ 회원 명단 (league_players)   ← 동호회 단위(시즌을 넘어 공유 — 지금도 그렇다)
     └─ 월렛 · 참가신청 · 드래프트    ← 기능 스위치로 켜고 끔
```

- **동호회 = 설정의 주인.** 시즌은 동호회 설정을 이어받고, 필요할 때만 덮어쓴다.
- **새 동호회는 모두 리그 시스템으로 만든다.** 옛 팀 시스템(PIN)으로 새로 만드는 길은 닫는다.

## 3. 표준화할 것 — 상세

### 3-A. 동호회 운영 설정 (`teams.settings`)

한 칸(jsonb)에 모은다. **빈 값 = 지금 미라클 동작**이 되도록 기본값을 잡아, 미라클은 아무것도 안 바뀐다.

| 묶음 | 키 | 미라클 값 | 지금 위치 | 쓰는 곳 |
|---|---|---|---|---|
| 경기 날 | `game_weekday` | 6(토) | `leagues.rsvp_rules`·문구 23곳 | 참가신청 창·마감·홈 카드·가이드 |
| | `signup_window` | 월 00:00~금 23:59 | `currentWindow()` 고정 | 참가신청 |
| | `capacity` | 18 | `rsvp_rules` | 참가신청 |
| 팀 구성 | `team_count` | 3 | 가정 | 로테이션·참가신청 보드 |
| | `rotation` | `winner_stays`(승자 잔류·2연속 휴식) | `rotation.ts` 고정 | 대진 자동 배정 |
| | `games_per_day` | 9~10 | `leagues.games_per_round` | 슬롯 생성 |
| 소속 | `roster_mode` | `quarter_draft` + `monthly_regular` | 기능 곳곳 | 팀 탭·명단·참가신청 |
| 기록 | `record_fouls` | false | 화면 곳곳(2026-11-09 뺌) | 기록 화면·박스스코어 |
| | `scoring` | +1 보너스·자유투 1구 2점 | `leagues.rules` | 그대로(시즌 단위 유지) |
| 영상 | `youtube_channel` · `title_rule` | 채널 · auto | `leagues.youtube_channel` | 영상 연동 |
| 월렛 | `wallet` (이름·계좌·가격·보너스·게스트비) | 미라클 월렛 | `teams.wallet_*` | 그대로 묶어 옮김 |
| 입금 자동 | `bank_auto.reserved_words` | 「모임통장」 | `depositorName.ts` | 입금 알림 |
| 표시 | `logo_url` | 미라클 로고 | `leagueLogo.ts` 하드코딩 | 잠금 화면·공유 그림 |

규칙: **설정을 읽는 함수는 하나**(`lib/club/settings.ts` 의 `loadClubSettings(teamId)` — 기본값 합치기 포함). 화면·라우트에서 기본값을 따로 적지 않는다.

### 3-B. 기능 스위치 (`teams.features`)

| 스위치 | 미라클 | 꺼지면 | 지금 판정 |
|---|---|---|---|
| `wallet` | 켬 | 월렛 메뉴·티켓·게스트비 포인트 사라짐 | `wallet_name` 있으면 |
| `rsvp` | 켬 | 홈 참가신청 카드·/rsvp 사라짐 | `leagues.rsvp_rules` 있으면 |
| `draft` | 켬 | 드래프트 메뉴 사라짐 | 어드민이면 보임 |
| `youtube` | 켬 | 영상 연동·하이라이트 탭 사라짐 | 채널 있으면 |
| `tournament` | 켬 | 대회 묶음 전환 사라짐 | 대회 묶음 있으면 |
| `uniform_photos` | 켬 | 달별 유니폼 사진 바꾸기 안 함 | 사진 있으면 |
| `bank_auto` | 켬 | 입금 알림 연결 칸 사라짐 | 연결 비밀번호 있으면 |
| `monthly_roster` | 켬 | 「달별 정규 멤버」 패널 사라짐 | 항상 |

- 판정 함수 하나: `hasFeature(club, 'wallet')`. 지금 흩어진 판정(「이름이 있으면」 등)을 이 함수로 바꾼다.
- 꺼진 기능의 **API 도 막는다**(화면만 숨기면 주소로 들어온다 — 대회 「일정 맞추기」에서 실제로 겪었다).

### 3-C. 화면 문구·가이드

- 「토요일」·「모임통장」·가격 같은 글자를 설정값으로 채운다(`clubText(settings)` 같은 작은 도우미).
- 회원 가이드(`memberGuide.ts`)·어드민 가이드(`adminGuide.ts`)는 **켜진 기능의 장만** 보이고, 가격·요일은 설정값으로 넣는다.
- 가이드 그림(`public/guide/*.png`)은 미라클 화면 캡처라 동호회 이름이 안 나오게 찍혀 있다(시험 데이터) → 그대로 써도 된다.

### 3-D. 하드코딩 걷어내기 목록 (2단계 작업 목록)

1. `lib/league/leagueLogo.ts` — 리그 id 매핑 → `teams.logo_url`(CEO 화면에서 올림)
2. 「토요일」 23곳 — `settings.game_weekday` 로. 날짜 계산(`currentWindow`·마감 자동)도 같이.
3. 「모임통장」·카카오뱅크 파싱 — 입금 알림 파서를 「은행별 해석기」로 나누고, 카카오뱅크를 첫 번째로 둔다.
4. 3팀 가정 — 참가신청 보드·로테이션이 팀 수를 설정에서 읽게.
5. 미라클 이름이 들어간 화면 문구 — 동호회 이름(`getClubName`)으로.
6. /admin 이벤트 내려받기 카드의 「미라클 리그」·「파란날개」 고정 문구 — 동호회 목록에서 고르게.

### 3-E. 데이터 구조

- **새 동호회 = 리그 시스템만.** `/admin/teams/new` 의 PIN 입력을 없애고, 만들 때 첫 시즌(`leagues` 한 줄)까지 같이 만든다.
- 파란날개 옮기기(6단계)는 별도 설계: `players`→`league_players`, `tournaments`/`games`→대회 묶음 `leagues(mode='tournament')`/`league_games`. CLAUDE.md 의 「대회 전용 팀에는 계정 체계가 없다」 4가지가 이 단계의 할 일이다. **선수 데이터 삭제 금지** 규칙은 옮긴 뒤에도 옛 표를 남겨 지킨다.

## 4. 1단계 상세 — /admin 개편

### 4-1. 바뀐 화면 구성

| 주소 | 내용 |
|---|---|
| `/admin` | **동호회 목록 하나**: 카드마다 이름·로고·시스템 배지(「리그」/「옛 팀」)·회원 수·이번 달 경기 수·켜진 기능 아이콘. 맨 위 「+ 새 동호회」. 숫자 칸(KPI)은 전체 합계로 한 줄. |
| `/admin/clubs/[teamId]` (새) | 동호회 상세 — 탭 5개: **기본 정보**(이름·주소·로고·공개) · **운영 설정**(3-A) · **기능**(3-B 스위치) · **시즌**(리그·대회 목록, 새 시즌) · **사람**(어드민 지정·회원 수·가입 대기) |
| `/admin/clubs/new` (새) | 새 동호회 마법사(4단계에서 완성, 1단계는 「이름·주소·로고 → 첫 시즌 자동 생성」까지) |
| `/admin/teams/*`, `/admin/leagues/*` | 남겨 두되 동호회 상세에서 링크로 들어간다(드래프트·어드민 패널 재사용). 옛 팀(파란날개)은 지금 화면 그대로. |
| 이벤트 내려받기 | 동호회 고르기 + CSV/JSONL |

### 4-2. 1단계에서 바꾸는 파일 (예상)

- `src/app/admin/(dashboard)/page.tsx` — 두 칸 → 동호회 목록
- `src/app/admin/(dashboard)/clubs/[teamId]/page.tsx` 새로 · 탭 컴포넌트 `components/admin/club/*`
- `src/app/api/admin/clubs/[teamId]/route.ts` 새로 (GET 상세 · PATCH 기본 정보) — 기존 `api/admin/teams/[teamId]` 를 넓혀도 됨
- `src/app/api/admin/export/events/route.ts` — `source` 대신 `teamId`
- `LeagueAdminRolePanel` 재사용(사람 탭)
- 1단계에서는 **DB 를 바꾸지 않는다**(운영 설정·기능 탭은 읽기 전용으로 지금 값을 보여 주기만). 쓰기는 2·3단계에서 칸을 만든 뒤.

### 4-3. 1단계 끝났다고 보는 기준

- /admin 첫 화면에서 미라클·파란날개가 같은 목록에 보이고, 각 동호회 상세에서 지금 설정(경기 수·신청 요일·월렛 가격 등)이 한 화면에 보인다.
- 미라클 회원 화면은 한 글자도 안 바뀐다(배포 전후 캡처 비교).

## 5. DB 변경안 (2~3단계, 실행 전 확인 필수)

```sql
-- 2단계: 운영 설정 · 로고
ALTER TABLE teams
  ADD COLUMN IF NOT EXISTS settings JSONB NOT NULL DEFAULT '{}'::jsonb,
  ADD COLUMN IF NOT EXISTS features JSONB NOT NULL DEFAULT '{}'::jsonb;
-- logo_url 은 이미 있다(teams.logo_url) — 미라클 값만 채운다.

-- 미라클은 지금 동작을 그대로 적어 둔다(빈 값이어도 기본값이 같지만, 화면에서 보이게)
UPDATE teams SET
  settings = '{"game_weekday":6,"capacity":18,"team_count":3,"rotation":"winner_stays","roster_mode":["quarter_draft","monthly_regular"],"record_fouls":false}',
  features = '{"wallet":true,"rsvp":true,"draft":true,"youtube":true,"tournament":true,"uniform_photos":true,"bank_auto":true,"monthly_roster":true}'
WHERE org_slug = 'miracle';
```

- 월렛 칸(`wallet_*`)·`leagues.rsvp_rules`·`games_per_round` 는 **바로 옮기지 않는다.** 읽는 함수(`loadClubSettings`)가 새 칸 → 옛 칸 순으로 읽게 해 두고, 화면이 다 바뀐 뒤 옮긴다(되돌리기 쉽게).

## 6. 미라클을 지키는 안전장치

1. **기본값 = 미라클 현재 동작.** 설정이 비어도 지금과 같게 돈다.
2. **단계마다 화면 비교**: 홈·참가신청·월렛·기록 화면을 시험 데이터로 배포 전후 캡처(기존 `zzshot` 방식)해 다른 곳이 없어야 배포.
3. **숫자 검증**: `node scripts/verify-scoring.mjs`(총득점 불변) · 리더보드·팀 탭 숫자 대조.
4. **한 번에 한 묶음**: 「토요일」 걷어내기처럼 범위가 넓은 일은 화면 하나씩 나눠 배포.
5. 문서: 단계가 끝날 때마다 CLAUDE.md 의 해당 규칙(「미라클은 …」)을 「동호회 설정 …(미라클 값 …)」으로 고쳐 쓴다.
