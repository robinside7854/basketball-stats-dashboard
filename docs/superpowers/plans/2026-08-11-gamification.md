# 게이미피케이션 확장 + 팀별 커스터마이징

작성 2026-08-11. 목적: **본인의 기록이 게임처럼 남게 해서 참여도를 올린다.**
사용자 확정 사항 — ① 보상 축 확장 먼저 ② 커스터마이징 범위는 켜기/끄기·임계값·이름/아이콘/색
(팀 전용 배지 신규 생성은 제외) ③ 과거 기록에 전체 소급.

## 2. 진단 — 지금 구조는 참여도 목적과 반대로 작동한다

활동 선수 37명의 `player_badges` 보유 분포 (2026-08-11 실측):

| 0개 | 1-2개 | 3-5개 | 6-10개 | 11개+ |
|---|---|---|---|---|
| **8명** | 10명 | 4명 | 7명 | 8명 (최다 30개) |

**배지 0개인 8명이 평균 28경기를 뛰었다.** 4종(퍼펙트게임·더블더블·트리플더블·위닝샷)이
전부 "잘하는 것"에 대한 보상이라 실력 순위를 그대로 복제한다. 하위권은 아무리 나와도 0개고,
화면은 "내가 뒤처졌다"만 확인시킨다.

### 그런데 B(19종)를 실제 데이터로 돌려 보면 다르다

`evaluateAllBadges()` 를 미라클 커리어 집계로 평가한 결과:

| 획득 수 | 0개 | 1개 | 2개 | 3개 | 4개 | 5개 | 9개 |
|---|---|---|---|---|---|---|---|
| 인원 | **3명** | 4명 | **14명** | 6명 | 6명 | 3명 | 1명 |

기존 배지 0개였던 8명 중 **6명이 즉시 배지를 갖는다**:

- 김명석(17경기) → 4개 · 배봉규(14경기) → 2개 · 강경호(62경기) → 2개
- 박의용(55경기) → 2개 · 한우평(14경기) → 4개 · 이호진(46경기) → 3개
- 남는 2명: 김태형·임준혁 (각 6경기 — `minGames` 미달, 출전이 적은 게 원인)

비율·스타일 기반(로드맨=공격리바 비중, 안전운반=낮은 턴오버, 남동타워=블록)이라
**득점이 적어도 자기 색깔로 받는다.** 이게 목적에 맞는 축이다.

## 3. 계획

### Phase 0 — 잠든 19종을 리그 트리에 노출 (최우선)

새로 만들 게 없다. 계산은 순수 함수라 DB 저장도, 마이그레이션도 필요 없다.

- `league/PlayerQuickViewModal`(과 `/me`)에서 `BadgeMasterbook` 을 띄운다
- 어댑터 1개: 리그 커리어 집계 → `PlayerCareerInput` + `TeamAverages`
  (`computeLeagueStats` 결과에 `shotBreakdown`·`astToTov` 를 채우면 그대로 들어간다)
- **소급은 자동** — 계산식이라 과거 기록이 이미 반영된다

효과: 배지 0개 8명 → 2명. 비용: 화면 연결 + 어댑터.

⚠ 검증 필요: 위 실측은 `doubleDoubles`/`tripleDoubles`/쿼터별 득점을 0으로 넣고 돌렸다
(리그 트리는 quarter 를 안 쓴다). `CLUTCH_Q4` 등 쿼터 의존 배지는 리그 트리에서 **항상 미획득**이
되므로, 그대로 노출하면 "영원히 못 받는 배지"가 목록에 남는다 → Phase 2 의 켜기/끄기로 가린다.

### Phase 1 — 누적·개인기록 축 추가

Phase 0 로도 안 풀리는 것: **출전이 적은 사람**(6경기)과 **"이번 주에 뭘 얻었나"**.

| 축 | 예시 | 저장 |
|---|---|---|
| 누적 | 10·25·50·100경기 출전, 누적 득점(=C 마일스톤과 통합), 개근 | `player_badges` |
| 개인 기록 | 커리어하이 득점/리바/어시, 첫 3점, 첫 더블더블 | `player_badges` |

- **C(마일스톤 PTS)를 흡수한다.** 새 시스템을 다섯 번째로 얹지 않는다.
- 개인 기록은 "갱신"이라 중복이 쉽게 생긴다 → 커리어 배지는 **(league_id, player_id, badge_type)
  유일**로 못 박는다(평생 1회). 지금 인덱스는 game 단위/라운드 단위 두 종류뿐이라
  **부분 유니크 인덱스 1개 추가 필요** (마이그레이션 1건).
- 전체 소급 재계산 필요 → 아래 비용 항목 참조.

### Phase 2 — 팀별 커스터마이징

범위(확정): **켜기/끄기 · 임계값 · 이름/아이콘/색**. 팀이 조건식을 새로 만드는 건 제외.

- 저장 위치: `leagues.badge_settings jsonb` (팀이 아니라 리그 단위 — 대회/리그마다 성격이 다르다)
- 형태: `{ "GLASS_EATER": { "on": true, "name": "리바운드 괴물", "icon": "💪", "thresholds": {...} } }`
- 코드 카탈로그(`BADGE_DEFINITIONS`)가 정본이고 DB 는 **override 만** 담는다 —
  정의를 통째로 DB 에 넣으면 코드와 DB 중 어느 쪽이 맞는지 알 수 없게 된다
- 임계값이 진짜 니즈인 이유: 미라클은 **10분 경기 9판**이라 더블더블이 160건(경기당 0.6)이다.
  40분 정규 경기 동호회는 완전히 다른 숫자가 맞다
- ⚠ **임계값을 바꾸면 과거 배지가 소급 변경된다.** "바꾸면 이렇게 바뀝니다" 미리보기 없이
  저장시키면 사고가 난다 → 저장 전 diff 표시를 Phase 2 범위에 포함

### Phase 3 — 개인 커리어 화면

`/me` 에 배지·마일스톤·커리어하이·다음 목표를 한 화면에. 게임처럼 보이는 지점은 여기다.

## 4. 자가검토 (비용·위험·보안)

- **재계산 비용**: 현재 배지 크론은 매일 05시 + 마감 훅, `maxDuration 300s`.
  Phase 1 은 261경기 × 37명 커리어 워크가 필요하다. **먼저 실측**하고 300초를 넘으면
  라운드 단위 증분(마지막 라운드만) + 전체 재계산은 스크립트로 분리한다.
- **인덱스**: `player_badges` 는 league/player/date 인덱스가 있다. 커리어 배지용 부분 유니크만 추가.
- **게스트 제외**: 2026-08-10 결정(게스트는 리더보드에서 제외)을 배지에도 동일 적용.
  `computeBadges` 는 현재 게스트를 거르지 않는다 → Phase 1 에서 같이 맞춘다.
- **보안**: 설정 변경은 `canEditLeague` 가드. 팀 어드민이 남의 리그 설정을 못 건드리게
  `leagueId` 스코프 확인 필수. PIN 폐지 방향에 따라 **새 가드는 어드민 role 기준**으로 만든다.
- **되돌리기**: Phase 1 소급 적용은 `player_badges` 에 행을 대량 추가한다. 배지 타입별로
  지울 수 있게 `badge_type` prefix 를 정해 두고(`career_*`), 실행 전 건수를 먼저 센다.
